# Swiss Grid Generator Quality Review

Date: 2026-05-11 10:17:52 CEST  
Reviewer: GPT-5

## 1. Overall Score

**7.7/10**

Swiss Grid Generator is a serious, technically mature typography tool with a strong canonical planning contract and unusually good export parity discipline. The best parts already match the spirit of `AGENTS.md`: deterministic planning, measured performance, strong tests, and restrained interaction. It is not yet a 10/10 Swiss instrument because the architecture is still concentrated in large orchestration files, `core/` is more transitional than real, the visual system still carries generic Tailwind/Radix residue, and the full test suite currently does not pass.

## 2. Category Ratings

- **Architecture & Code Structure: 8.0/10**  
  The `PageExportPlan` contract is real: preview builds from `buildPageExportPlan` and then consumes canvas render plans in `webapp/gui/preview/hooks/useTypographyRenderer.ts`, while export preplans pages before PDF/SVG/IDML rendering in `webapp/lib/export-engine.ts`. Weakness: `webapp/core/types/export-plan.ts` is still a bridge back to `lib`, so the promised pure `core/` boundary is incomplete.

- **Code Quality & Cleanliness: 7.0/10**  
  Lint and TypeScript pass, and naming is generally deliberate. But complexity is high: `useShellModel.tsx` is 2447 lines, `GridPreview.tsx` is 2175, and `page-export-plan.ts` is 1945. That is too much load-bearing orchestration for "less, but better."

- **Design & UI Adherence: 7.0/10**  
  The live app is calm, sparse, and clearly more disciplined than the older screenshots. However, `DESIGN.md` asks for strong borders instead of shadows, while `SwissCanvas.tsx`, popups, and tooltips still use shadowed/card-like treatment. Color also drifts from Braun restraint: `webapp/lib/config/color-schemes.ts` includes several saturated palettes.

- **Editorial Voice & Text Quality: 8.0/10**  
  In-app text is strong. The typed i18n boundary in `webapp/lib/i18n/messages.ts` and the text-quality contract in `webapp/tests/contracts/text-quality-contract.test.mjs` are serious safeguards. Repo-facing copy is weaker: README language remains more promotional than editorial.

- **Maintainability & Future-proofing: 7.2/10**  
  The test taxonomy, generated content pipeline, and contract tests are good. The main risks are stale paths in tests, very large files, and the incomplete migration from `lib` to `core`.

- **Technical Foundation: 8.5/10**  
  Strong stack: Next 15, React 19, Zustand 5, strict TypeScript, workers, deterministic font-file metrics, export workers, and focused scripts in `webapp/package.json`. This is one of the project's strongest areas.

- **User Experience & Polish: 7.7/10**  
  The workflow is deep and professional: presets, multi-page documents, layers, smart zoom, deterministic preview, PDF/SVG/IDML export. The UI feels functional and precise, but not yet fully resolved as a high-end Braun/Swiss instrument.

## 3. Strengths

1. The canonical `PageExportPlan` model is implemented, not just documented.
2. PDF/SVG/IDML export parity is well protected through shared planning and contract tests.
3. Typography and text metrics are treated seriously, with browser metrics kept out of the layout contract.
4. Product text is mostly routed through generated locale content and typed i18n.
5. Performance work is measured and documented, consistent with `PERFORMANCE.md`.

## 4. Weaknesses & Risks

1. **Full test suite is currently not clean.** `npm test` fails because `webapp/tests/integration/font-roundtrip.test.mjs` references the old `components/preview/PreviewWorkspace.tsx` path. `test:core` also fails in `grid-reduction-validation.test.mjs` with an `EISDIR` loader/runtime error under the current Node.
2. **Architecture is still too concentrated.** Large files make future changes risky and slow to review.
3. **`core/` is not yet the real domain center.** It currently contains only 122 lines of type bridges and imports from `lib`.
4. **Visual primitives are not fully authored.** `webapp/app/globals.css` globally suppresses rounding/shadows instead of the component system being designed from first principles.
5. **Design doctrine and implementation disagree in places.** `DESIGN.md` specifies Braun palette and `Space Grotesk`, but the implemented UI mainly uses Inter and broader color schemes.
6. **Generated artifacts can churn during validation.** `prelint` and `pretest:integration` run `assets:generate`, which can touch tracked preset output.

## 5. Prioritized Recommendations

1. Fix the failing test paths and the `test:core` loader failure first. A serious typography tool cannot carry a broken `npm test`.
2. Split `useShellModel.tsx`, `GridPreview.tsx`, and `page-export-plan.ts` into smaller controllers, planners, and adapters.
3. Complete the `core/` migration in real slices: document model, layout planning, export planning, then GUI adapters.
4. Replace generic UI primitive defaults with an explicit Swiss/Braun component system: no global correction layer as the main design mechanism.
5. Reconcile `DESIGN.md` with implementation: either adopt the declared typography/palette or update the doctrine to match the actual product.
6. Reduce color schemes to fewer, more defensible editorial palettes with clear functional roles.
7. Rewrite README and repo-facing copy in the same calm, non-promotional voice enforced in the app; source text should use normal case while GUI text is lowercased by CSS.
